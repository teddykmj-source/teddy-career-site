## 🟢 초급 (팁 1~9) — 기본기

### 1. `/init`으로 세션 시작 `[00:11]`
- 기존 프로젝트에 Claude Code를 처음 투입할 때 `/init`을 실행하면 프로젝트 구조·기술 스택을 분석해 **CLAUDE.md 파일을 자동 생성**한다.
- CLAUDE.md는 이후 모든 세션에서 프로젝트 맥락으로 로드되므로, 시작점으로 반드시 만들어 둘 것.

### 2. 스테이터스 라인(Status Line) 설정 `[00:52]`
- 터미널 하단에 **사용 중인 모델, Git 브랜치, Remaining Context(남은 컨텍스트)** 등을 상시 표시.
- 컨텍스트가 얼마나 남았는지 눈으로 확인하면서 작업하면 아래의 `/compact` 타이밍을 잡기 쉽다.

### 3. `/context`로 토큰 소모 분석 `[02:28]`
- 어떤 파일이나 액션이 **컨텍스트를 과도하게 점유하는지** 찾아낸다.
- 대화가 무거워졌다고 느껴지면 먼저 `/context`로 원인을 진단할 것.

### 4. `/compact` & `/clear` 활용 `[03:02]`
- **컨텍스트가 60% 이상 찼을 때**가 정리 신호.
- `/compact`: 대화를 요약해 컨텍스트를 압축. `/clear`: 완전히 새로 시작.
- 작업 단위가 끝났으면 `/clear`로 리셋하는 것이 품질에 유리하다.

### 5. 플랜(Plan) 모드로 시작 `[03:51]`
- 실제 파일을 수정하기 전에 **분석·계획 단계**를 거치게 하는 모드.
- 플랜 모드에 진입하면 AI가 **질문을 통해 요구사항을 명확히 가다듬은 뒤** 계획을 제시하므로 실수를 크게 줄일 수 있다.

### 6. 역질문 유도하기 `[05:39]`
- 프롬프트에 *"내가 원하는 바를 95% 이상 이해할 때까지 나에게 질문해"* 같은 문구를 추가.
- 모호한 지시로 인한 잘못된 구현을 사전에 차단하는 초급 핵심 팁.

### 7~9. 클로드가 스스로 점검하게 만들기 (영상 설명 기반)
- 영상 설명에 따르면 초급 파트 후반은 **"클로드가 스스로 질문하고 점검하게 만드는 프롬프트"**를 다룬다.
- 작업 완료 후 "구현이 요구사항을 충족하는지 스스로 검증해", "테스트를 돌려 확인해" 같은 자가 점검 지시를 습관화하는 내용.

## 🟡 중급 (팁 10~20) — 워크플로우 확장

### 10. 서브 에이전트(Sub-agent) 병렬 실행 `[07:11]`
- 조사·탐색 같은 작업을 서브 에이전트에게 위임하면 **메인 대화의 컨텍스트를 아끼면서** 여러 작업을 병렬로 처리할 수 있다.

### 11. 나만의 스킬(Skill) 제작 `[08:48]`
- **반복되는 프롬프트 패턴은 `.claude/skills/`에 스킬로 저장**해 두고 `/스킬명`으로 호출.
- 자주 하는 작업(예: 코드 리뷰 체크리스트, 배포 절차)을 스킬화하면 매번 긴 프롬프트를 칠 필요가 없다.

### 12. CLAUDE.md 효율적으로 관리하기
- 세션 중 알게 된 규칙·실수를 CLAUDE.md에 **자동으로 반영·생성하도록 설정**해 프로젝트 기억을 축적.
- 단, 무한정 길어지면 매 세션 토큰을 잡아먹으므로 핵심 규칙 위주로 유지.

### 13. `/rewind`로 되돌리기
- 잘못된 방향으로 간 코드를 말로 고치라고 반복 지시하는 것보다, **`/rewind`로 이전 정상 시점(체크포인트)으로 되돌리는 것**이 빠르고 깨끗하다.

### 14. 훅(Hooks) 알림 세팅 `[15:11]`
- 작업 완료 시 **사운드 알림이나 슬랙 통지**가 오도록 훅을 설정.
- 여러 세션을 동시에 돌릴 때(다중 작업) 어느 작업이 끝났는지 바로 알 수 있다.

### 15. 시각 자료(이미지/캡처) 적극 활용
- 말로 설명하기 어려운 UI 버그·디자인은 **스크린샷을 붙여넣는 것**이 가장 정확한 커뮤니케이션이며 작업 효율을 크게 올린다.

### 16. 디자인/웹사이트 레퍼런스 템플릿화 `[16:37]`
- 마음에 드는 사이트를 **캡처한 이미지를 레퍼런스로 제공**해 그 스타일을 템플릿처럼 재사용.

※ 중급 파트의 나머지 항목(17~20)은 스니펫에서 개별 확인이 안 되었으나, 영상 설명 기준으로 위 주제들(서브 에이전트, 스킬, CLAUDE.md, /rewind, hooks, 이미지 레퍼런스)의 세부 활용법으로 구성된다.

## 🔴 고급 (팁 21~28) — 고수의 영역

### 21. Git Worktree로 안전한 병렬 개발 `[17:09]`
- 같은 저장소를 **worktree로 여러 작업 폴더로 분리**해, 파일 충돌 없이 여러 Claude 세션이 동시에 다른 기능을 개발.

### 22. MCP 대신 직접 API 엔드포인트 활용 `[18:31]`
- **필요한 기능이 단일 기능이라면** 무거운 MCP 서버를 붙이는 것보다 직접 API 엔드포인트를 호출하게 하는 편이 토큰·복잡도 면에서 낫다.
- MCP는 도구 정의만으로도 컨텍스트를 차지하므로 선택 기준을 갖출 것.

### 23. `/loop` 예약 및 주기적 작업 `[18:52]`
- `/loop` 명령으로 **"5분마다 배포 상태 확인"** 같은 반복·예약 작업을 자동화.

### 24. 원격 컨트롤 (claude remote-control) `[19:19]`
- 원격 모드를 켜면 **스마트폰(모바일)에서** 데스크톱에서 돌아가는 Claude Code 세션을 제어할 수 있다. 자리를 비워도 작업 진행 확인·지시 가능.

### 25. 데이터베이스 직접 연동 `[20:14]`
- DB 세션을 연결하면 Claude Code를 **데이터 분석가처럼** 활용해 쿼리·분석을 시킬 수 있다.

### 26. `ultrathink` 활용 `[20:37]`
- 프롬프트에 `ultrathink`를 넣으면 **사고 예산(thinking budget)을 최대로 확장**해 복잡한 문제에서 답변 품질이 올라간다.

### 27. `settings.json` 권한 관리 `[21:23]`
- `rm -rf`, `git push --force` 같은 **위험한 명령을 deny 목록으로 차단**해 두면, 권한 확인 없이 달리는 자율 주행 모드(auto-accept)의 안전성이 높아진다.

### 28. 에이전트 팀(Agent Team) 구상 `[22:15]`
- 단순히 병렬 작업만 하는 서브 에이전트와 달리, **기획자·개발자·리뷰어처럼 역할을 나눈 에이전트들이 협업하는 팀**을 구성하는 방식. 영상의 마지막이자 최고급 활용법.
